# 工作文件 · 本地文件档案工具

一个纯前端的本地文件归档工具：归档、检索、查看、统计、备份，数据只存在浏览器里，不上传、不联网。

## 能做什么

- **归档**：拖入或拍照导入文件，按系列/文件夹归类，自动从文件名解析日期；导入 `.zip` 会自动解包成多条记录（压缩包本身不入库）
- **检索**：文件名、表格字段、Word/PDF/文本正文、图片 OCR 文字一起搜，命中后直接跳进文件定位
- **查看**：Word（docx）、Excel（xlsx/csv）、PDF、图片、纯文本内置预览；PDF 的文字可以选中复制；命中词高亮并放大，表格同步标出命中的行列表头
- **统计**：按系列出表格、导 CSV
- **备份**：整库导出 zip，换设备导入还原
- **同步**：两种方式。①**局域网中转**（推荐，需在本机跑 `工作文件/server.js`；想继续用线上 https 地址，用 `启动服务-https.bat` 并在面板里填一次地址）：电脑端点「开启中转」，平板扫一个网址就自动连上、自动同步，之后电脑有改动会自动推过去，不用再扫码；②**扫码直连**：同一 WiFi 下手机扫电脑二维码，配对码自动瘦身适配多网卡设备，传完自动对账，缺的会重传。两种方式文件都只在这两台设备之间流动，不经过第三方服务器。文件多或单个文件很大时，改用「导出备份 → 手机端合并导入」更稳

## 跑起来

```bash
cd 工作文件
node server.js          # 默认 5173 端口
node server.js --https  # 自签证书，线上 https 页面要自动配对时用这个
```

打开 `http://127.0.0.1:5173/`。也可以用任意静态服务器托管 `工作文件/` 目录，`server.js` 只是本地开发用的静态服务（带安全头与路径拦截）。

## 目录

```
工作文件/            应用本体（index.html + js + css + vendor + sw.js）
docs/               架构说明、恢复指南、现状 PRD
tests-workfile/     回归测试用的合成样例（不含真实资料）

```

## 线上部署

push 到 `main` 后由 `.github/workflows/pages.yml` 自动发布 `工作文件/` 到 GitHub Pages，访问 `https://<用户名>.github.io/Dsearch/`。

`server.js` 在 Pages 上不参与运行，静态托管足够。只有**局域网中转同步**需要在本机启动它（`/api/relay/*`）。用 http 启动时访问 `http://本机IP:5173/`；用 `--https` 启动时，在线上页面的同步面板填一次 `https://本机IP:5173`，即可不换网址自动配对（首次需允许证书例外与本地网络访问）。扫码同步在 Pages 上也能用。

## 隐私与安全

- 应用数据存在使用者本机浏览器的 IndexedDB 里，仓库和线上页面都拿不到
- 仓库不含访问口令、账号、密钥、数据库连接，也不含个人工作文件
- 测试样例全部是合成的，正文为通用的中性内容（不含任何真实资料）
- 文档里的本机路径统一用 `~/Desktop/Dsearch` 占位

局域网中转服务（`server.js` 的 `/api/relay/*`）的边界：

- 只接受本机与私网来源，公网地址一律 403；校验 `Host`、`Origin`、`Sec-Fetch-Site`，挡 DNS rebinding 与跨站请求
- 只转发两段 SDP 文本，**不接触文件内容**，不写磁盘、不记日志；会话一次性、单客户端、闲置十分钟销毁
- 配对码 5 分钟内最多尝试 10 次；电脑端可随时踢掉客户端或关闭会话
- 文件本身走 WebRTC 数据通道，由 DTLS 端到端加密，与扫码直传的强度相同
